## II. ARCHITECTURE CONSTITUTION (FSD Layers)

### Layer Stack: IMMUTABLE

```
app/ (Orchestration)
  ↓ (never reverse)
widgets/ (Composition)
  ↓ (never reverse)
features/ + entities/ + shared/ (Implementation)
```

**NOTHING bypasses this stack.** No exceptions without amendment.

### Layer 1️⃣: `app/` — ORCHESTRATION ONLY

**What it is:** Next.js App Router + routing semantics  
**What it does:** Extract params, render one widget, handle loading/error states  
**What it NEVER does:** Business logic, API calls, complex state

**Binding Rules:**

- One page file = one `return` statement = render one widget (or layout)
- No filtering, sorting, validation, mutations
- No `useEffect` for data fetching
- All dynamic state lives in widget/features, not page components

**Pattern (Canonical):**

```tsx
// app/[locale]/dashboard/employees/page.tsx
export default function EmployeesPage({
  searchParams,
}: {
  searchParams: Record<string, string>;
}) {
  const page = parseInt(searchParams.page ?? "1");
  const sort = searchParams.sort ?? "fio";

  // That's it. One widget.
  return <EmployeesWidget pageNumber={page} initialSort={sort} />;
}
```

### Layer 2️⃣: `widgets/` — COMPOSITION + ORCHESTRATION

**What it is:** Self-contained UI section combining multiple features  
**What it does:** Manage widget-level state, coordinate features, handle UI flow  
**What it NEVER does:** API calls directly (only through features), unrelated business logic

**Binding Rules:**

- Widget = orchestrator of features + state curator
- Widget state = intersection logic (selected item, tab index, filters, pagination)
- Features communicate via callbacks + prop drilling (no global state within widget)
- Structure: inside `widgets/{domain}/` OR standalone `.tsx` file

**Pattern (Canonical):**

```tsx
// widgets/ai-assistant/chat/index.tsx → orchestrates chat + artifacts + insights
"use client";
import { useState } from "react";
import { ChatFeature } from "@/features/ai-assistant/chat";
import { ArtifactsFeature } from "@/features/ai-assistant/artifacts";

export function ChatWidget() {
  const [selectedArtifactId, setSelectedArtifactId] = useState<string | null>(
    null,
  );

  return (
    <div className="grid gap-4">
      <ChatFeature onArtifactGenerated={setSelectedArtifactId} />
      {selectedArtifactId && (
        <ArtifactsFeature artifactId={selectedArtifactId} />
      )}
    </div>
  );
}
```

### Layer 3️⃣: `features/` — BUSINESS LOGIC + UI

**What it is:** Single-responsibility user action handler (list, create, edit, delete, analyze)  
**What it does:** Validates input, orchestrates entity hooks + store state, renders feature UI  
**What it NEVER does:** Directly export from pages, call APIs without entity hooks

**Binding Rules:**

- One feature directory = one user action
- Must use entity hooks (never direct API calls without entity layer)
- Must have: `ui/`, `lib/hooks.ts`, `store.ts` (if state needed)
- State = Zustand store for feature-local state
- Max dependency = features on entities, not vice versa

**Structure (Canonical):**

```
features/ai-assistant/chat/
├── ui/
│   ├── chat-interface.tsx      # Presentational
│   ├── message-list.tsx
│   ├── input-area.tsx
│   └── suggested-prompts.tsx
├── lib/
│   ├── hooks.ts                # useChatMessages, useChatInput, etc.
│   └── store.ts                # Zustand for chat state
└── model/
    └── types.ts                # ChatMessage, UserMessage, etc.
```

### Layer 4️⃣: `entities/` — DATA MODELS + APIs

**What it is:** Domain models + how to fetch/mutate them via GraphQL  
**What it does:** GraphQL documents, codegen types, Apollo hooks, Zod schemas  
**What it NEVER does:** Render UI, handle user actions, aggregate data

**Binding Rules:**

- One entity folder = one data model
- GraphQL files live here: `api/queries/*.graphql`, `api/mutations/*.graphql`
- Apollo hooks wrap generated types in `api/queries/hooks/`, `api/mutations/hooks/`
- Zod schemas in `model/` for validation
- Re-export everything through `index.ts`

**Structure (Canonical):**

```
entities/core/employee/
├── model/
│   ├── types.ts                # Employee, Grade, types
│   └── schema.ts               # Zod employeeCreateSchema
├── api/
│   ├── queries/
│   │   ├── getEmployee.graphql
│   │   ├── getEmployees.graphql
│   │   ├── hooks/
│   │   │   ├── useGetEmployee.ts
│   │   │   ├── useGetEmployees.ts
│   │   │   └── index.ts
│   │   └── index.ts
│   ├── mutations/
│   │   ├── createEmployee.graphql
│   │   ├── updateEmployee.graphql
│   │   ├── hooks/ (same structure)
│   │   └── index.ts
│   └── index.ts                # export queries + mutations
└── index.ts                    # export model + api
```

### Layer 5️⃣: `shared/` — INFRASTRUCTURE

**What it is:** Reusable infrastructure (UI, GraphQL client, utilities, theme)  
**What it does:** Connect to GraphQL, provide shadcn components, host utilities  
**What it NEVER does:** Know about domain entities or features

**Binding Rules:**

- No domain logic
- UI components must be presentational (shadcn, custom composables)
- Stores: `graphql/` for Apollo, `theme/` for theme, `i18n/` for translations
- Lib functions: pure utilities, no dependencies on entities/features

**Core Subdirectories:**

```
shared/
├── graphql/                    # Apollo Client, codegen config
├── ui/                         # shadcn + custom components
├── stores/                     # Global Zustand (auth, company)
├── lib/                        # Utilities (date, format, parse)
├── constants/                  # UPPER_SNAKE_CASE constants
├── i18n/                       # Translations
└── theme/                      # Theme setup
```

## III. NAMING CONTRACTS (Locked In)

### A. File Names — IMMUTABLE

| Type       | Pattern                  | Example                                         |
| ---------- | ------------------------ | ----------------------------------------------- |
| Components | `kebab-case.tsx`         | `chat-interface.tsx`, `employee-table.tsx`      |
| Hooks      | `use[Noun].ts`           | `useChatMessages.ts`, `useFormValidation.ts`    |
| Stores     | `[name].store.ts`        | `chatStore.ts`, `auth.store.ts`                 |
| Utilities  | `camelCase.ts`           | `formatDate.ts`, `calculateCapacity.ts`         |
| Folders    | `kebab-case`             | `ai-assistant/`, `chat-message/`                |
| GraphQL    | `[verb][Entity].graphql` | `getEmployee.graphql`, `createEmployee.graphql` |

**VIOLATIONS are bugs.** No exceptions.

### B. Exports — CANONICAL

| Type           | Export Name                              | Example                                   |
| -------------- | ---------------------------------------- | ----------------------------------------- |
| Component      | `PascalCase`                             | `export function ChatInterface() {}`      |
| Hook           | `use[Purpose]`                           | `export function useChatMessages() {}`    |
| Store          | `use[Name]Store`                         | `export const useChatStore = create(...)` |
| Utility        | `camelCase`                              | `export function formatDate() {}`         |
| Type/Interface | `PascalCase`                             | `export type ChatMessage = { ... }`       |
| Enum           | `PascalCase` + `UPPER_SNAKE_CASE` values | `enum Status { ACTIVE = "active" }`       |
| Constant       | `UPPER_SNAKE_CASE`                       | `export const MAX_FILE_SIZE = ...`        |

**NO EXCEPTIONS.** Not "IUser" interfaces, not "\_private" utilities.

### C. TypeScript Types — CANONICAL

```typescript
// ✅ Correct

interface UserSession {
  userId: string;
  token: string;
}
enum EmploymentStatus {
  ACTIVE = "active",
  DISMISSED = "dismissed",
}
type CreateEmployeeInput = { fio: string; departmentId: string };

// ❌ Wrong
interface IEmployee {} // No I prefix
type employee = {}; // Lowercase
```

## V. GRAPHQL + CODEGEN FLOW (Source of Truth)

### A. Document Structure (Canonical)

**Query Files:**

```graphql
# entities/core/employee/api/queries/getEmployee.graphql
query GetEmployee($id: ID!) {
  employee(id: $id) {
    id
    fio
    departmentId
    gradeId
    status
  }
}
```

**Mutation Files:**

```graphql
# entities/core/employee/api/mutations/createEmployee.graphql
mutation CreateEmployee($input: CreateEmployeeInput!) {
  createEmployee(input: $input) {
    id
    fio
    departmentId
  }
}
```

### B. Codegen Flow

1. **Discovery:** Codegen finds all `.graphql` files in:
   - `shared/graphql/client/**`
   - `entities/**/api/queries/**`
   - `entities/**/api/mutations/**`

2. **Generation:** Generates to `shared/graphql/generated/graphql.ts`:
   - `GetEmployeeDocument` (TypedDocumentNode)
   - `GetEmployeeQuery` (response type)
   - `GetEmployeeQueryVariables` (input type)

3. **Hook Wrapping:** Entity hooks import + wrap generated types:

```typescript
// entities/core/employee/api/queries/hooks/useGetEmployee.ts
"use client";
import { useQuery } from "@apollo/client";
import {
  GetEmployeeDocument,
  type GetEmployeeQuery,
  type GetEmployeeQueryVariables,
} from "@/shared/graphql/generated";

export function useGetEmployee(variables: GetEmployeeQueryVariables) {
  return useQuery<GetEmployeeQuery, GetEmployeeQueryVariables>(
    GetEmployeeDocument,
    { variables, fetchPolicy: "cache-and-network" },
  );
}
```

**Rule:** Codegen types are SINGLE SOURCE OF TRUTH. Never manually override.

## VI. STATE MANAGEMENT (Three-Tier System)

### Tier 1: Apollo Cache (Server State)

- **Scope:** Any data fetched from GraphQL
- **Lifetime:** Persisted across page navigation
- **Use:** Entity queries/mutations
- **Tool:** `@apollo/client`

### Tier 2: Zustand Stores (Feature State)

- **Scope:** Feature-local UI state (filters, sort, pagination, selected items)
- **Lifetime:** Lives in widget/feature component memory
- **Use:** `features/{domain}/{feature}/store.ts`
- **Tool:** `zustand`

**Canonical Store Pattern:**

```typescript
// features/ai-assistant/chat/lib/store.ts
"use client";
import { create } from "zustand";
import type { ChatMessage } from "../model/types";

interface ChatStore {
  messages: ChatMessage[];
  isLoading: boolean;
  addMessage: (msg: ChatMessage) => void;
  clearMessages: () => void;
}

export const useChatStore = create<ChatStore>((set) => ({
  messages: [],
  isLoading: false,
  addMessage: (msg) => set((state) => ({ messages: [...state.messages, msg] })),
  clearMessages: () => set({ messages: [] }),
}));
```

### Tier 3: URL State (Navigation)

- **Scope:** Page-level state (page, sort, filters)
- **Use:** `searchParams` in page props
- **Pattern:** `?page=2&sort=fio&filter=active`

**Rule:** Never duplicate data across tiers. Single source wins.

## VII. COMPONENT HIERARCHY (Sharp Distinctions)

### ① Components (Dumb/Presentational)

- **Props:** Only data + callbacks
- **Logic:** Zero (just render)
- **Example:** `Button`, `Card`, `Table`, `Modal`, `Badge`
- **Location:** `shared/ui/` or shadcn

### ② Feature Components (Smart)

- **Props:** Feature-specific (filters, onSelect, etc.)
- **Logic:** Handle user actions via feature hooks
- **State:** May use feature store
- **Location:** `features/{domain}/{feature}/ui/`

### ③ Widget Components (Orchestrators)

- **Props:** Minimal (page params)
- **Logic:** Compose features + manage inter-feature communication
- **State:** Widget-level only (selected item, tab)
- **Location:** `widgets/`

**Clean Dependency Chain:**

```
Dumb Comp ← Feature Comp ← Widget ← Page
(no state)  (feature store) (widget state) (params only)
```

## VIII. AI ASSISTANT ARCHITECTURE (Reference Implementation)

### Layers

**Entity Layer:** `entities/ai-assistant/`

- Types: `ChatMessage`, `Artifact`, `Insight`
- GraphQL: chat message queries/mutations
- Hooks: `useGetMessages()`, `useSendMessage()`

**Feature Layer:** `features/ai-assistant/`

- `chat/` — message list, input, suggestions
- `artifacts/` — code/content viewer, generation
- `insights/` — batch queries, analysis display

**Widget Layer:** `widgets/ai-assistant/`

- Combines chat + artifacts + insights
- Manages message selection → artifact display
- Orchestrates user flows

### Key Decisions (Locked In)

1. **Streaming:** Done at route handler level (`/api/ai/analyze`), not widget
2. **Message Persistence:** GraphQL mutations to database (not ephemeral)
3. **Artifacts:** Separate entity from messages (can be generated from multiple sources)
4. **Caching:** Apollo cache for queries, SSE for streaming analysis

## XIII. CODE QUALITY STANDARDS (Non-Negotiable)

### TypeScript

- ✅ Strict mode enabled
- ✅ No `any` types (use `unknown` + type guard)
- ✅ Exhaustive type checking in conditionals
- ✅ Generics over function overloads

### React

- ✅ Functional components only
- ✅ Hooks only in components, never conditionally
- ✅ Mark client components with `"use client"`
- ✅ No prop drilling beyond 2 levels (use store/context)
- ✅ Keys on list items must be stable IDs

### GraphQL

- ✅ Queries fragmented by entity
- ✅ Mutations return full updated object
- ✅ Always request `__typename` for cache
- ✅ Use `refetchQueries` or cache updates post-mutation

### Formatting

- ✅ ESLint + Prettier configured (run before commit)
- ✅ Max line length: 100 characters
- ✅ No trailing semicolons (semicolon-free)
- ✅ Import order: `react` → `@` aliases → relative
